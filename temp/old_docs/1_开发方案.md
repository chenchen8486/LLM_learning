# Transformer 深度学习工程 — 开发方案

> 本文档是整个学习工程的「设计基准」与「操作手册」。任何章节 HTML 的开发、构建、风格规范均以本文件为准。
> 创建时间：2026-06-17　|　最近更新：2026-06-17

---

## 1. 工程目标

对 5 篇视觉 Transformer 经典论文进行**深度拆解精讲**，沉淀为一套可离线浏览、带侧边栏导航、含 LaTeX 公式渲染与配图的结构化 HTML 学习手册。

- **学习对象**：`ref_paper/` 下 5 篇论文的中文翻译稿与配图。
- **产出形态**：复用 `IOS_software_design/output/html` 的成熟构建体系（片段 → 构建脚本 → 套模板生成带导航成品），并针对论文学习增强**公式渲染、配图自动复制、要点回顾卡片**。
- **防幻觉红线**：所有讲解内容必须以 `ref_paper` 原文为依据，逐节通读后再编写，严禁凭记忆编造公式、数据或结论。

---

## 2. 工作流程（核心约定）

本工程采用**逐章迭代、先样板后批量**的工作方式，不做一次性全量生成：

```
① 通读论文原文  →  ② 产出该章全部小节 HTML  →  ③ 用户浏览确认
        ↑                                              │
        │                                              ▼
   ⑥ 批量推进下一章  ←  ⑤ 沉淀/更新生成规范  ←  ④ 迭代打磨格式与内容
```

1. **逐篇通读**：编写某章前，先用 Read 完整读取对应论文 `*_zh.md`，掌握结构、配图文件名、公式与数据表。
2. **整章产出**：一次性产出该章所有小节片段，运行构建，让用户看到完整章节效果（导航、翻页、公式、配图、表格全要素）。
3. **用户确认**：用户在浏览器中阅读，就视觉风格、内容深度、细节取舍给出反馈。
4. **迭代打磨**：根据反馈调整，直至该章满意。第 1 章作为**风格样板章**，定稿后即冻结格式基线。
5. **沉淀规范**：将定稿格式约定固化到本文档第 6-7 节（生成规范），作为后续章节的硬约束。
6. **批量推进**：以样板章为模板，逐章推进第 2-6 章，每章产出后仍走「确认 → 打磨」闭环。
7. **统一精修**：全部章节完成后，用户通读推敲，一起做最后一轮内容与细节优化。

## 6. 构建体系说明

### 6.1 构建流程

1. 在 `output/html/pages/` 下新建片段，命名 `{年份}{论文缩写}_{章节序号}_{英文短名}.html`（如 `2016Attention_1_introduction.html`）。
   - 每个大章节一个 HTML 文件，该章节下的所有子章节（如 3.1、3.2.1）全部写在该文件中。
   - 章节序号约定：`0`=摘要，`1-N`=正文，`8` 及以后为附录/可视化。
2. 运行 `python output/html/build.py`，脚本自动完成：
   - 扫描所有片段，提取 `<h1>` 标题、正文、`<style>`、`<script>`；
   - 按文件名推导章节层级，生成**侧边栏导航树 + 面包屑 + 上下节翻页**；
   - 解析正文中 `src="images/{年份}{论文缩写}/..."` 的图片引用，从 `ref_paper/*/images/` **自动复制**同名图片到 `output/html/images/{年份}{论文缩写}/`；
   - 套用 `template.html` + `global.css`，输出成品 HTML。
3. 章节标题映射在 build.py 顶部 `CHAPTER_TITLES` 配置；新增章节时同步维护。

### 6.2 关键配置项（build.py 顶部）

| 配置 | 作用 |
|------|------|
| `CHAPTER_TITLES` | 章号 → 顶层导航/面包屑标题 |
| `PAPER_TO_CHAPTER` | 新文件名中的 `{年份}{论文缩写}` → 章号映射（如 `2016Attention` → 1） |
| `NAV_GROUPS` | 旧格式三级小节的分组标题（如 `ch6_1` → "6.1 演进图谱"），新格式下每个大章节一个文件，一般不再使用 |
| `REF_PAPER_DIR` | 配图源目录，默认 `../../ref_paper` |

## 7. HTML 编写规范（格式基线）

> 以第 1 章为样板，所有章节须遵循下列约定，保证全手册风格统一。

### 7.1 通用约定

- **编码**：所有文件统一 `utf-8-sig`（跨平台兼容）。
- **片段结构**：`<article class="content"> … </article>`，可选前置 `<style>` 与后置 `<script>`。
- **标题**：每个片段必须含唯一 `<h1>`，build 据此提取页面标题。
- **副标题**：`<p class="subtitle">` 标注「对应论文章节 + 整理时间」，便于溯源。
- **配图引用**：统一写 `src="images/{年份}{论文缩写}/<原始图片名>"`（如 `images/2016Attention/f7896a22….jpg`），图片名照抄 `ref_paper` 中的文件名，由 build.py 自动复制。

### 7.2 标准组件清单

| 组件 | class | 用途 |
|------|-------|------|
| 快速浏览卡片 | `.doc-meta-card` | 每节开头：核心问题、本文主张、关键词标签 |
| 术语详解卡片 | `.term-card` | 初学者友好：术语中英文 + 通俗解释 + 生活类比 |
| 原创示意图 | `.diagram` + 内联 SVG | 自制示意图，须标注「非论文原图」 |
| 重点框 | `.highlight-box` / `.warn` / `.danger` / `.info` | 绿=要点、黄=注意、红=易错、蓝=补充说明 |
| 概念卡片网格 | `.concept-grid` + `.concept-card` | 并列概念对照（如 Q/K/V） |
| 公式卡片 | `.formula-card` + `.formula-note` | 居中公式 + 下方一句话解读 |
| 配图（单） | `.img-block` | 单张论文配图，支持点击放大 |
| 配图（并排） | `.img-row`（`.cols-3` 三列） | 多图并排 |
| 表格容器 | `.table-wrap` | 包裹 `<table>`，支持横向滚动 |
| 要点回顾卡片 | `.socratic-card` | 每节末尾：3 组「问 + 关键补充」轻量小结 |

### 7.3 公式书写

- 行内公式用 `\( … \)`，行间公式用 `\[ … \]`，由 KaTeX 自动渲染。
- 论文 md 中的 `$…$` / `$$…$$` 需在编写时转换为上述定界符。
- 复杂多行公式可在一个 `.formula-card` 内连写多个 `\[ … \]`。

### 7.4 内容编写原则

- **每节结构**：快速浏览卡片 → 分级讲解（h2/h3）→ 关键公式/配图/表格 → 要点回顾卡片。
- **讲解风格**：先给直觉/类比，再上公式；重要结论用重点框突出。
- **承上启下**：适当点出与前作/后续论文的关系，呼应「演进主线」。
