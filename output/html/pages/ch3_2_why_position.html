3.2 为什么需要位置编码：注意力是个「脸盲」

核心问题Embedding 告诉模型「每个 token 是什么」，但 Transformer 的注意力天生不看顺序。「第几个出现的 token」这条信息从哪来？
本节主张纯自注意力是置换等变的：把输入 token 打乱，输出只是跟着重排，数值一点不变。它把句子当「集合」而非「序列」，语序信息必须额外注入。
一句话结论绝对位置编码给每个位置发一个向量加在 token 上，相对位置编码让注意力计算时直接感知两个 token 相距多远；选哪种深刻影响模型的长度外推能力。

　　3.1 节把 token 变成了向量，模型知道了「每个词是什么」。但这些向量马上要送进注意力层，而注意力有一个天生的盲区：它认得出每个 token，却认不出 token 的顺序。本节先把这个盲区用最直接的方式摆出来，再给出它的数学名字，最后引出补位置信息的两条路线：

  1. 一个思想实验：把句子打乱（3.2.1）：亲手做一次打乱输入的实验，看注意力的输出到底发生了什么；
  2. 语序即语义：顺序本身就是意思（3.2.2）：「狗咬人」和「人咬狗」说明顺序丢了，意思就丢了一半；
  3. 「脸盲」的数学表述：置换等变（3.2.3）：这个盲区的正式名字，后面几节会反复用到；
  4. 两条解决路线：绝对位置 vs 相对位置（3.2.4）：发门牌号还是见面问距离，两派方案一次分清；
  5. 本章地图（3.2.5）：接下来的 3.3、3.4、3.5 三节各自讲什么。

　　读完全节，你要能独立讲清两件事：为什么注意力天生「脸盲」，以及绝对位置与相对位置两条路线的分水岭在哪。这两件事是 3.3 到 3.5 节所有技术细节的地基。

3.2.1 一个思想实验：把句子打乱

　　上一节讲过，Embedding 层把每个 token ID 变成一个向量。到这里，模型知道了「这句话里有哪些词」。接下来这些向量会被送进一摞 Transformer 层做注意力计算（第 4 章的主题）。在正式拆开 Transformer 之前，先做一个思想实验，它能暴露注意力机制一个天生的盲区。

　　实验很简单：把「我 / 爱 / 大语言 / 模型」四个 token 的向量喂给一个不带位置编码的注意力层，记下每个 token 的输出向量；然后把输入打乱成「模型 / 爱 / 大语言 / 我」，再喂一次。直觉上，输入顺序变了，输出总该跟着变吧？实际发生的事恰恰相反：每个 token 的输出向量数值一点没变，只是按新顺序重新排了一遍。「我」在两次实验里得到的输出完全相同，它根本不知道自己第一次站在队首、第二次站在队尾。

原创示意图 · 非论文原图
图示：同一句子的两种排列喂给不带位置编码的注意力层，每个 token 的输出数值完全相同（颜色与数字一一对应），只是顺序跟着重排。

　　这个现象不是 bug，而是注意力的计算方式决定的。注意力算的是「任意两个 token 之间的相关程度」：每个 token 都和所有 token 两两匹配一次，再把结果加权求和。整个过程没有任何一步用到「这个 token 排第几」。所以注意力对语序天然是「盲」的：它知道哪些 token 在场，却不知道谁排在谁前面。

3.2.2 语序即语义：顺序本身就是意思

　　分不清顺序，问题有多严重？看这组中文例子：

狗咬人。
人咬狗。

　　两句话由完全相同的三个 token 组成，意思却完全相反：谁是动作的发出者、谁是承受者，全部编码在顺序里。对一个「脸盲」的模型来说，这两句话是同一个集合 {狗，咬，人}，算出的表示一模一样，它没有任何线索知道两句话的意思相反。

　　这样的例子在中文里俯拾皆是。「我请你吃饭」和「你请我吃饭」，人情方向完全颠倒；「屡战屡败」和「屡败屡战」用字全同，一个是丧气汇报，一个是顽强表态。人类语言的语义有相当一部分就装在词序里，读不出顺序，等于丢了一半的信息。

　　所以 Transformer 必须有办法感知位置。原论文对此写得非常直白：

由于我们的模型不包含循环和卷积，为了让模型利用序列的顺序信息，我们必须注入关于序列中令牌相对或绝对位置的信息。
—— Vaswani et al., Attention Is All You Need，第 3.5 节

3.2.3 「脸盲」的数学表述：置换等变

　　这个盲区在数学上有个正式名字，值得记住，后面几节会反复用到：

置换等变 Permutation Equivariant permutation（置换）+ equivariant（等变）= 输入怎么换顺序，输出就跟着怎么换顺序

「等变」指一种「跟着变」的性质。对注意力来说：把输入 token 的顺序任意打乱（置换），输出的内容不变，只是顺序跟着同样打乱。它意味着注意力把输入当成一个无序的集合，而不是一串有先后的序列。

　　用公式写出来。设 \(X\) 是 \(n\) 个 token 的向量排成的矩阵，\(\pi\) 表示任意一种打乱顺序的操作（置换），那么：

\[ \mathrm{Attention}(\pi X) \;=\; \pi\,\mathrm{Attention}(X) \tag{1} \]
公式 (1)：先打乱再算注意力，与先算注意力再打乱，结果完全一样。注意力不创造任何顺序信息，输入怎么排，输出就怎么排。

　　对比一下前代架构就明白这有多特殊：RNN 一个词一个词按顺序读进来，顺序天然烙在计算过程里；CNN 的卷积核也有固定的左右结构。Transformer 为了追求并行效率，让所有位置同时计算，代价就是把顺序信息弄丢了。位置编码的任务，就是把这块信息补回来。

有研究（Kazemnejad et al., 2023）发现，GPT 类模型的因果掩码会泄露少量先后信息：第 \(i\) 个位置只能看到前 \(i\) 个 token，这本身已是一种位置线索，所以 decoder-only 模型不加显式位置编码也能学到部分语序。但「相距多远」它依然感知不到，主流模型仍离不开专门的位置编码，这一点 3.4 节再展开。

3.2.4 两条解决路线：绝对位置 vs 相对位置

　　补位置信息的方案分成两大流派，区别用一个类比就能说清。给小区住户定位：一种思路是发门牌号，每栋楼钉一块牌子，1 号楼、2 号楼，住户报出号码就知道自己在哪；另一种思路不发门牌号，见面问距离，任意两户碰面，先问一句「咱们两家隔几栋楼」。前一种是绝对位置编码，后一种是相对位置编码。

对比维度绝对位置编码相对位置编码
核心思想给每个位置发一个「门牌号」向量不标门牌号，让 token 两两感知「相距多远」
代表方法正弦编码（Transformer 原版）、可学习编码（GPT、BERT）RoPE（旋转位置编码）、ALiBi
注入位置输入端：位置向量直接加在 token 向量上注意力内部：改造两两匹配的内积（QK 内积，见 3.4 节）或给注意力分数加偏置
模型感知到「我排在序列的第几位」「我们两个隔多远、谁前谁后」
长度外推偏弱：训练时没见过的位置，没有现成的向量可用偏强：距离规律不随序列变长而失效（ALiBi 的论文标题就叫 Train Short, Test Long）

　　两派的分歧不只是工程口味。绝对位置编码把「第 512 位」这样的信息写死在向量里，训练时没见过第 513 位，推理时就没有现成的表示可用（可学习编码是表里少了这一行，正弦编码虽能算出数值、模型却没学过怎么用）；相对位置编码只学「距离 3 是什么意思」，这条规律不随序列变长而失效。这就是为什么位置编码的选择会一路影响模型的长度外推能力，也就是第 3.5 节的主线。

自注意力天生是个「脸盲」：认得出每个 token，认不出 token 的顺序，位置编码是 Transformer 唯一的位置信息来源。绝对位置编码发「门牌号」，相对位置编码量「间距」。当代主流 LLM（LLaMA、Qwen、DeepSeek 等）几乎一边倒地选择了相对阵营的 RoPE，3.4 节细讲原因。

🧭本节要点回顾
为什么说不加位置编码的注意力是个「脸盲」？
注意力是置换等变的：输入 token 怎么打乱，输出只是跟着重排，每个 token 的输出数值不变。它把句子当集合而非序列，认得出 token，认不出顺序。
「狗咬人」和「人咬狗」对纯注意力模型来说是什么关系？
完全是一回事。两者的 token 集合相同，模型算出的每个 token 表示一模一样；两句话意思相反这件事，它无从得知，语序承载的语义对它全部丢失。
绝对位置编码和相对位置编码的分水岭在哪里？
前者给每个位置发固定的「门牌号」向量加在 token 上（正弦编码、可学习编码），后者不标绝对位置，让注意力计算时直接感知两个 token 的距离（RoPE、ALiBi）。这个选择深刻影响长度外推能力，是 3.5 节的主线。
