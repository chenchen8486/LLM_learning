4.2 注意力机制：Query、Key、Value 的分工

本页范围：第 4 章第 2 节　|　整理时间：2026-09-29

快速浏览

核心问题一个 token 更新自己的表示时，应该听句子里哪些 token 的、各听多少？
本节主张注意力机制让每个 token 用 Query 主动报出需求，用 Key 亮出名片供人匹配，用 Value 提供真正的内容；按"匹配打分 → 缩放 → softmax → 加权求和"四步，把相关 token 的信息按比例搬进自己的新表示。
一句话结论Attention(Q,K,V) = softmax(QKᵀ/√d_k)V：先算谁和谁相关，再按相关程度把内容加权取回来。
关键词
Query / Key / Value缩放点积注意力softmax 权重加权求和掩码并行计算

　　4.1 节搭起了两塔骨架，注意力是骨架里最关键的引擎，这一节把它拆到底。要回答的问题很具体：一个 token 更新自己的表示时，该听句子里哪些 token 的、各听多少？本节按"先直觉、再公式、后手算"的主线推进：

  1. 注意力在解决什么问题：每个 token 该听谁的（4.2.1）：静态词向量装不下语境，RNN 的接力传话又慢又丢信息，注意力让每个 token 直接环顾全句；
  2. Query、Key、Value：三个角色各司其职（4.2.2）：同一个向量乘三个投影矩阵，分出"需求、名片、内容"三种身份；
  3. 公式拆解：四步完成一次注意力（4.2.3）：匹配打分、缩放、softmax、加权求和，并讲清为什么要除以 √d_k；
  4. 手算一遍：3 个 token、4 维向量的完整推演（4.2.4）：用能跟着算的小数字把四步走完，看清注意力权重这张分配表；
  5. 同一个公式，三种用法（4.2.5）：编码器自注意力、解码器掩码自注意力、编码器-解码器注意力，区别只在 Q、K、V 从哪里来、每个位置能看哪些位置；
  6. 为什么注意力取代了循环（4.2.6）：用原论文的复杂度对比表收账——换来 O(1) 的顺序操作与信息路径，代价是 O(n²) 的计算量。

　　读完全节，softmax(QKᵀ/√d_k)V 这个公式对你来说应该不再是一串符号，而是"先算谁和谁相关，再按相关程度取内容"这四步的速写。

4.2.1 注意力在解决什么问题：每个 token 该听谁的

　　第 3 章讲过，Embedding 层给每个 token 查出一个静态向量：只要 token 相同，查出来的向量就相同。但语言的意思高度依赖语境。"苹果"在"我吃了一个苹果"和"苹果发布了新手机"里指的东西完全不同；"小猫追蝴蝶，因为它饿了"里的"它"指谁，也必须看了上下文才能确定。静态向量装不下这些信息，模型还缺一层机制：让每个 token 看一眼整句话，再决定自己的新表示要融入谁的信息。

　　在 Transformer 之前，这个活儿主要靠循环神经网络（RNN）干：从头到尾逐个读词，每读一个词更新一次记忆，靠记忆把前文的信息带到现在。这种做法有两个硬伤：信息必须一站一站往后传，隔得越远越容易丢失；而且必须按顺序计算，第 100 个词要等前 99 个算完才能开工，GPU 的并行能力用不上。原论文第 1 节正是从这两个痛点出发，提出完全抛弃循环结构。

　　注意力机制换了一条路：不搞接力传话，让每个 token 直接环顾全句。它主动向所有 token（包括自己）发出询问：你和我关系有多紧密？然后按紧密程度把对方的信息按比例搬过来，融合成自己的新表示。隔得再远的两个 token 也能一步到位直接对话，而且所有 token 的询问可以同时进行。

　　所以这步在干嘛：注意力给每个 token 一次"向全句提问并收集答案"的机会，把静态的词向量升级为结合上下文的新表示。这一步怎么做，就是本节的主题。

4.2.2 Query、Key、Value：三个角色各司其职

　　注意力机制把一次"提问"拆成三个角色，每个 token 都会同时扮演这三个角色：

Query（查询）

这个 token 想找什么。由它主动发出，拿去和所有 token 的 Key 做匹配。

Key（键）

这个 token 的名片，标注自己能提供什么信息，用来被别人的 Query 匹配。

Value（值）

这个 token 真正提供的内容。名片一旦被看中，被取走的就是它。

　　这三者的关系，可以想象成在图书馆查资料：你走到咨询台报出自己的需求（Query），书目系统里每本书都有一张索引卡片，写着书名和关键词（Key）。你拿需求和卡片逐一对照，卡片只是判断哪本书相关的线索；真正被你借走、读进脑子里的，是书的内容（Value）。需求和哪张卡片对得上，就重点取哪本书的内容，对不上就少取甚至不取。

点积（Dot Product） dot product = 两个向量对应分量相乘，再全部相加

点积是最常用的向量相似度度量：两个向量长度相当时，方向越一致，点积越大；方向越无关（接近垂直），点积越接近 0。注意力机制正是用 Query 和 Key 的点积来衡量"需求"和"名片"有多匹配。

　　三个角色并不是三个互不相干的向量，而是同一个 token 向量乘以三个不同投影矩阵变出来的。第 3 章得到的 token 向量 \(x\)，分别乘上三个可学习的权重矩阵 \(W^Q\)、\(W^K\)、\(W^V\)，就得到这个 token 的 \(q = xW^Q\)、\(k = xW^K\)、\(v = xW^V\)。这三个矩阵是训练出来的参数，模型通过学习不断调整"该怎么描述需求、该怎么写名片、该怎么提供内容"。同一个 token 因此身兼三职：既去查别人（Query），也被别人查（Key），还随时准备好被取走内容（Value）。

Query、Key、Value 是同一个 token 向量的三种化身：投影矩阵 \(W^Q\)、\(W^K\)、\(W^V\) 让模型学会从三个角度描述每个 token。注意力要做的，就是用 Query 和 Key 算出"该听谁的"，再从 Value 里把信息取回来。

　　原论文中每个 token 向量的维度是 \(d_{\text{model}} = 512\)；实际实现用了 8 个并行的注意力头，每个头里 Query、Key 的维度 \(d_k = 64\)，Value 的维度 \(d_v = 64\)（即 \(512 \div 8\)）。多头是下一节的主题，本节先用单头的视角把原理讲透。

4.2.3 公式拆解：四步完成一次注意力

　　原论文把这套机制命名为缩放点积注意力（Scaled Dot-Product Attention），全部计算浓缩在一个公式里：

\[ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V \tag{1} \]
公式 (1)：缩放点积注意力（原论文公式 (1)，逐字核对）。\(Q\)、\(K\)、\(V\) 是把所有 token 的 Query、Key、Value 分别堆成的矩阵，输出同样是每个 token 一行的新矩阵。符号说明：\(Q,K,V\) 由输入向量乘投影矩阵 \(W^Q,W^K,W^V\) 得来（4.2.2 节），每行对应一个 token；\(K^{\top}\) 是 \(K\) 的转置，\(QK^{\top}\) 算出所有 token 两两之间的匹配分；\(d_k\) 是 Key 向量的维度，\(\sqrt{d_k}\) 是缩放因子，防止点积过大把 softmax 推进梯度极小的区域；softmax 把每行分数归一化成和为 1 的权重；最后乘 \(V\) 即按权重对 Value 加权求和。

　　从右往左读会晕，按计算顺序拆成四步就清楚了：

  1. 匹配打分 \(QK^{\top}\)：每个 Query 和每个 Key 做点积，得到一个 \(n \times n\) 的分数矩阵（\(n\) 是 token 数），第 \(i\) 行第 \(j\) 列表示 token \(i\) 对 token \(j\) 的看中程度。这步在干嘛：算出谁和谁相关。
  2. 缩放：所有分数除以 \(\sqrt{d_k}\)。这步在干嘛：把分数拉回合适的数值范围，防止下一步 softmax 被撑爆（原因下文细说）。
  3. softmax 归一化：对分数矩阵的每一行做 softmax，把一行分数变成和为 1 的权重。这步在干嘛：把看中程度换算成分配比例，每个 token 手里的注意力总预算是 1，按比例分给所有 token。
  4. 加权求和：用权重矩阵去乘 \(V\)，输出的第 \(i\) 行就是所有 token 的 Value 按第 \(i\) 行权重的加权和。这步在干嘛：按比例把别人的内容搬进自己的新表示。
\[ \mathrm{softmax}(z_i) = \frac{e^{z_i}}{\sum_{j} e^{z_j}} \]
softmax 把任意一行实数变成和为 1 的比例：指数运算放大分数之间的差距，分母负责归一化。原始分数差一点，权重可能差出好几倍。符号说明：\(z_i\) 是这一行第 \(i\) 个原始分数；\(e^{z_i}\) 是它的指数（\(e\) 是自然常数）；\(\sum_j e^{z_j}\) 是对整行所有分数的指数求和，作分母把结果归一化。

　　配上张量形状看得更清楚。设序列有 \(n\) 个 token，Query 和 Key 是 \(d_k\) 维，Value 是 \(d_v\) 维：

\[ \underset{n \times d_k}{Q}\;\cdot\;\underset{d_k \times n}{K^{\top}}\;=\;\underset{n \times n}{S}\;\xrightarrow{\;\div \sqrt{d_k},\ \mathrm{softmax}\;}\;\underset{n \times n}{W}\;\cdot\;\underset{n \times d_v}{V}\;=\;\underset{n \times d_v}{\text{输出}} \]
中间那个 \(n \times n\) 矩阵是注意力的指挥表：每一行是一个 token 对所有 token 的注意力分配。符号说明：\(n,d_k,d_v\) 的含义见上一段（token 数、Key 维度、Value 维度）；\(S\) 是缩放前的分数矩阵；\(W\) 是 softmax 之后每行和为 1 的注意力权重矩阵；矩阵下方的标注是各自的形状。

为什么要除以 √d_k

　　原论文 3.2.1 节给出的理由是：当 \(d_k\) 较大时，点积的数值会变得很大，从而把 softmax 函数推进梯度极小的区域；为了抵消这种影响，用 \(1/\sqrt{d_k}\) 缩放点积。梯度极小意味着参数几乎收不到更新信号，模型在这一层就学不动了。

一个帮助理解的定量直觉：若 Query、Key 各分量是相互独立、均值为 0、方差为 1 的随机数，点积是 \(d_k\) 个分量乘积之和，其标准差约为 \(\sqrt{d_k}\)。\(d_k = 64\) 时，分数的典型波动就有 ±8 上下。softmax 对差距极其敏感：分差放大 8 倍，\([1, 0]\) 的 softmax 结果会从 \([0.73, 0.27]\) 变成 \([0.9997, 0.0003]\)，几乎变成胜者全拿，输家那边的梯度趋近于 0。除以 \(\sqrt{d_k}\)（\(d_k = 64\) 时即除以 8）恰好把波动拉回单位尺度。这是后人的直觉解释，论文原文只给出"点积变大导致 softmax 饱和"的结论。
原论文 3.2.1 节还对比过两种打分方式：加性注意力用一个带单隐藏层的小前馈网络计算匹配度；点积注意力就是公式 (1) 去掉缩放因子。两者理论复杂度相当，但点积可以直接调用高度优化的矩阵乘法，实践中更快、更省显存。只是 \(d_k\) 较大时，未缩放的点积注意力会落后于加性注意力，论文的对策正是加上缩放因子 \(1/\sqrt{d_k}\)，缩放点积注意力由此得名。今天的 LLM 几乎清一色使用缩放点积注意力。

4.2.4 手算一遍：3 个 token、4 维向量的完整推演

　　公式看完，用一个能跟着算的小例子过一遍。三个 token 组成一句话："我 爱 猫"。为演示方便，假设投影已经完成，每个 token 的 Key 和 Value 如下，维度 \(d_k = d_v = 4\)（示例数字，仅为演示，不代表真实模型的计算结果）：

向量token 1「我」token 2「爱」token 3「猫」
\(k\)（名片）\([2,\ 0,\ 0,\ 0]\)\([0,\ 0,\ 2,\ 0]\)\([0,\ 1,\ 0,\ 0]\)
\(v\)（内容）\([1,\ 0,\ 2,\ 1]\)\([0,\ 2,\ 1,\ 1]\)\([2,\ 1,\ 0,\ 0]\)

　　现在算 token 1「我」这一个位置的新表示，它的 Query 是 \(q_1 = [1,\ 0,\ 1,\ 0]\)。

　　第 1 步，匹配打分。让 \(q_1\) 和三个 Key 分别做点积：

  • \(q_1 \cdot k_1 = 1\times2 + 0\times0 + 1\times0 + 0\times0 = 2\)
  • \(q_1 \cdot k_2 = 1\times0 + 0\times0 + 1\times2 + 0\times0 = 2\)
  • \(q_1 \cdot k_3 = 1\times0 + 0\times1 + 1\times0 + 0\times0 = 0\)

　　「我」和自己的名片、和「爱」的名片都对上了，和「猫」完全没对上。

　　第 2 步，缩放。\(\sqrt{d_k} = \sqrt{4} = 2\)，三个分数都除以 2：

\[ \frac{[2,\ 2,\ 0]}{\sqrt{4}} = [1,\ 1,\ 0] \]

　　第 3 步，softmax。\(e^1 \approx 2.718\)，\(e^0 = 1\)，分母 \(= 2.718 + 2.718 + 1 = 6.437\)：

\[ \mathrm{softmax}([1,\ 1,\ 0]) = \left[\frac{2.718}{6.437},\ \frac{2.718}{6.437},\ \frac{1}{6.437}\right] \approx [0.422,\ 0.422,\ 0.155] \]
三个权重加起来正好是 1。这就是 token 1 手里的注意力分配表。

　　第 4 步，加权求和。用这三个权重去加三个 Value：

\[ o_1 = 0.422 \times [1,\ 0,\ 2,\ 1] + 0.422 \times [0,\ 2,\ 1,\ 1] + 0.155 \times [2,\ 1,\ 0,\ 0] \approx [0.73,\ 1.00,\ 1.27,\ 0.84] \]
token 1 的新表示：约 84% 的内容来自「我」和「爱」，16% 来自「猫」。可以抽查第 2 个分量：\(0.422\times0 + 0.422\times2 + 0.155\times1 = 1.00\)，刚好凑整。

　　所以这步在干嘛：四步走完，「我」不再是最初那个静态向量了，它把句子里相关 token 的内容按比例揉进了自己体内。注意力权重就是一张"该听谁的"的分配表，模型在看谁、看多少，一目了然。

　　以上只是分数矩阵的第 1 行，也就是 token 1 一个词的计算。token 2、token 3 用各自的 Query 重复同样的过程，各算一行。三行互不依赖，可以同时算完。请记住"互不依赖"这四个字，4.2.6 节会用到它。

图示：以 token 1（\(q_1\)）为例的注意力计算流。\(q_1\) 与所有 Key 点积得到匹配分，缩放后经 softmax 变成权重，再乘到 Value 上求和得到输出。图中数字与 4.2.4 节的手算例子一致（示例数字，仅为演示）。

4.2.5 同一个公式，三种用法

　　缩放点积注意力这个公式，原论文在 Transformer 里用了三次（3.2.3 节），区别只在 Q、K、V 从哪里来、每个位置能看哪些位置：

编码器自注意力

Q、K、V 全部来自编码器前一层的输出。每个 token 都能看到同句所有 token，没有任何限制。

解码器自注意力（带掩码）

Q、K、V 来自解码器前一层，但每个位置只允许看自己及之前的位置。做法是把 softmax 输入中所有对应非法连接的分数设为 \(-\infty\)，softmax 之后这些位置的权重变成 0。

编码器-解码器注意力

Q 来自解码器前一层，K、V 来自编码器的输出。解码器借此回头查输入句子的每一个位置。

　　前两种用法的 Q、K、V 同源，所以叫自注意力（self-attention）；第三种的 Q 与 K、V 不同源，常叫交叉注意力（cross-attention），主要服务机器翻译这类输入一种语言、输出另一种语言的场景。今天主流的 GPT 类模型只保留解码器，只用带掩码的自注意力这一种用法：生成第 \(n\) 个词时看不到第 \(n\) 个词之后的内容，这就是模型不能剧透未来的原因。掩码的实现细节与因果生成的关系，本章后续小节还会展开。

　　所以这步在干嘛：同一台发动机，接三种不同的油箱。理解句子时（编码器）随便看，生成文字时（解码器）只许回头看，翻译对照时（交叉注意力）一头看原文、一头写译文。

4.2.6 为什么注意力取代了循环

　　回到本节开头的问题，现在可以给注意力一个公正的评价。RNN 像击鼓传花的传话游戏：一句话从第一个人传到最后一个人，传得越远越走样，而且必须排队，快不起来。注意力像把所有人拉进一个群聊：每个人直接跟所有人对话，同时开口，距离再远也是一步到位。

　　原论文第 4 节用一张表把这种差别量化（表 1）：

层类型每层复杂度顺序操作数最大路径长度
自注意力\(O(n^2 \cdot d)\)\(O(1)\)\(O(1)\)
循环\(O(n \cdot d^2)\)\(O(n)\)\(O(n)\)
卷积\(O(k \cdot n \cdot d^2)\)\(O(1)\)\(O(\log_k(n))\)
自注意力（受限）\(O(r \cdot n \cdot d)\)\(O(1)\)\(O(n/r)\)

　　表 1（原论文表 1）：\(n\) 是序列长度，\(d\) 是表示维度，\(k\) 是卷积核大小，\(r\) 是受限自注意力的邻域大小。重点看右边两列。顺序操作数衡量能不能并行：自注意力每个位置的新表示互不依赖（4.2.4 节手算例子里三行就是各算各的），全部位置可以同时算，GPU 终于能火力全开。最大路径长度衡量远距离信息要走几步：自注意力任意两个位置一步直连，隔了 50 个词的指代也能一把抓住，而 RNN 要传 50 站。

　　代价也写在表里：每层复杂度中的 \(n^2\)。序列长度翻倍，注意力的计算量翻两番。

\(n^2\) 是注意力为"任意直连"付的账单。今天的长上下文需求（几万到上百万 token）让这项开销成为系统瓶颈，怎么给注意力减负，是第 5 章（GQA、MLA 等架构变体）和第 13 章（KV Cache、推理优化）要解决的问题。
一句话：注意力用 \(O(n^2)\) 的计算量，换来 \(O(1)\) 的顺序操作和 \(O(1)\) 的信息路径。计算量可以靠堆 GPU 并行消化，顺序依赖和长路径却是 RNN 绕不开的结构性瓶颈。这就是 Transformer 取代 RNN 的根本原因。
🧭本节要点回顾
Query、Key、Value 三个角色分别负责什么？它们从哪里来？
Query 描述这个 token 想找什么，Key 是供人匹配的名片，Value 是真正被取走的内容。三者由同一个 token 向量分别乘可学习投影矩阵 \(W^Q\)、\(W^K\)、\(W^V\) 得到。
为什么点积之后要除以 \(\sqrt{d_k}\) 再做 softmax？
原论文 3.2.1 节的理由：\(d_k\) 较大时点积数值变大，会把 softmax 推进梯度极小的饱和区，模型学不动。除以 \(\sqrt{d_k}\) 把分数拉回合适的数值范围。
注意力凭什么取代 RNN？
任意两个位置一步直连（最大路径长度 \(O(1)\)），且所有位置的新表示互不依赖、可以并行计算（顺序操作数 \(O(1)\)）。代价是 \(O(n^2)\) 的计算量，但它能被并行硬件消化。
