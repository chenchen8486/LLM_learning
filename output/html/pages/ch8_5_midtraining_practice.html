8.5.1 四家方案对比：同一个配方，四种写法

　　本节挑的四家是公开资料里中期训练细节最充分的代表：Meta 的 Llama 3.1（arXiv:2407.21783，三阶段配方写得最完整）、阿里的 Qwen2.5（arXiv:2412.15115，渐进式扩展与推理侧外推的组合拳）、深度求索的 DeepSeek-V3（arXiv:2412.19437，把扩展成本压到极限）、面壁智能与清华的 MiniCPM（arXiv:2404.06395，小模型方法论模板，WSD 调度器的出处）。关键事实全部取自各家技术报告原文，横向对比如下：

　　表格装的是骨架，逐家补一段血肉。Llama 3.1 是「照章办事」的典范：预训练明确分 initial pre-training、long context pre-training、annealing 三段。长上下文段分六轮、消耗约 800B token，每升一档长度都要先过两道验收关才进下一轮。最有反差感的是退火：只用最后 40M token（相对 15.6T 主训连零头都算不上），就把 8B 模型在 GSM8k 和 MATH 验证集上的成绩分别相对拉高 24.0% 和 6.4%；而 405B 旗舰几乎不涨，Meta 的解读是旗舰的上下文学习能力已经足够强，不需要这种定向投喂。Meta 还发明了退火的副业——评估新数据源的质量：把 50% 训完的 8B 模型在 40B token 上退火，新数据按 30% 混入，涨不涨分一测便知。

　　Qwen2.5 把「分阶段」玩出了花样。开源系在预训练收尾阶段一次把 4K 扩到 32K，同时用 ABF 把 RoPE 基频从 1 万抬到 100 万；Turbo 则是四阶段渐进，每阶段的训练数据固定为 40% 当前满长序列加 60% 更短序列——长短混喂，明确保住短任务。更值得注意的是它的「训练 32K、标称 131K」组合：训练侧只扩到 32K，推理侧再叠 YARN 与 DCA 把可用长度外推 4 倍。训练扩展与推理外推分工，正是 8.2 节两条路线的合体实战。

　　DeepSeek-V3 是省钱教科书。长度扩展两阶段合计只耗 11.9 万 H800 GPU 小时，约占主训 266.4 万小时的 4.5%，就把 4K 主训模型变成 128K。省钱的诀窍有三：YaRN 只施加在 MLA 的解耦共享键这一条位置支路上；每阶段只训 1000 步；学习率不做任何调整，直接沿用主训收尾的 \(7.3 \times 10^{-6}\)，不重新 warmup。它的主训学习率本身也是分段式的（恒定 → cosine 衰减 → 末段 500B 再分两小步降到 \(7.3 \times 10^{-6}\)），与 MiniCPM 的 WSD 异曲同工——稳定段占绝对大头，衰减集中在末尾。

　　MiniCPM 是小模型玩家的方法论模板，两个原创贡献都直击资源痛点。一是「模型风洞实验」：像飞机设计吹风洞一样，先在 0.009B 到 0.5B 的小模型上把 batch、学习率扫干净，再外推到 2.4B（实测最优学习率稳定在 0.01 附近，不随规模漂移）。二是 WSD 调度器：稳定段想训多久训多久，需要交货时退火约 10% token 就出终模，中间 checkpoint 全部可复用；配套消融还证明了一条重要经验——高质量数据放在退火段，比匀进整个预训练或只留给 SFT 收益更大。它家的 MiniCPM-128K 则完整示范了「稳定段 checkpoint → 44% 长数据续训 → 128K」的链路，2.4B 体量在 ∞Bench 上超过 6B 的 ChatGLM3-128K。

Polyak 平均（checkpoint 平均） Polyak averaging = 把一段训练轨迹上的多个 checkpoint 权重求平均

Llama 3.1 在退火阶段每隔一段存一个 checkpoint，终模不取最后一个点，而是取这些权重的逐参数平均。末段学习率虽小，参数仍在一个极小值盆地边缘来回晃动，平均相当于把晃动抵消掉，落在盆地更平坦的中心，泛化通常更好。

就像评定期末成绩不看最后一次模拟考，而取最近几次的平均分——单次发挥有运气成分，平均下来才是真实水平。
四份方案，骨架惊人一致：主训阶段用短上下文把算力花在刀刃上，中期再花小钱扩长度；长上下文一律靠「改 RoPE ＋ 长数据短训」获得，没有一家为此从头重训；收尾一律上高质量数据（退火），并用 checkpoint 复用或平均榨干主训价值。差异只在工程取舍：扩多长、分几段、混多少长数据、退火多陡。

8.5.2 minimind 视角：小模型要不要中间训练

　　看完大厂，镜头拉回本工程。minimind 的「中间训练量」是多少？答案是零：预训练脚本把每条样本截断到 340 token（--max_seq_len 默认值，train_pretrain.py 第 90 行，注释写明「中文 1 token ≈ 1.5 到 1.7 字符」，340 token 大约五百来个汉字），配套预训练数据也全是清洗后的短文本。这个模型从出生起就没见过超过 340 token 的序列。

　　但先别急着说它「先天不足」——翻翻配置会发现作者把弹药提前备好了。MiniMindConfig 里 RoPE 基频默认 \(10^6\)、位置表预算到 32768（model_minimind.py 第 29、27 行），频率表从初始化那天起就覆盖 32K 个位置；配置里还躺着一个 YaRN 开关（第 31 到 39 行）：打开 inference_rope_scaling，就按「原始长度 2048、放大 16 倍」做推理期缩放。也就是说，位置编码这一侧万事俱备，缺的只有数据和训练。

　　于是「把 minimind 从 340 扩到 2048」这个假想实验，改动清单短得惊人：

  1. 数据侧（核心改动）：按 8.3 节的手法构造长数据——把短文档拼接、或收集真正的长文档，做出一份平均长度覆盖 2K 的预训练 jsonl；训练时把 --max_seq_len 从 340 改成 2048，数据集类的截断与补齐逻辑会自动适配。
  2. 位置编码侧（不用改）：2048 只是 340 的 6 倍，而按 8.2 节算过的账，基频 \(10^6\) 的最长波长足以覆盖数万位置，2K 远在安全区内。想演示 ABF 才需要动基频，本实验不必。推理期想再往外推，打开内置 YaRN 开关即可。
  3. 训练侧（续训而非重训）：用 --from_weight 从预训练 checkpoint 接着训，学习率比主训的 \(5 \times 10^{-4}\) 低一个量级（比如 \(5 \times 10^{-5}\) 到 \(10^{-4}\)），几百步收工——这正是 DeepSeek-V3「沿用收尾学习率、不重新 warmup」思路的微缩版。
  4. 验收（双测）：短文本能力不能退（对比续训前后的短文本困惑度与生成体感）；长文要能捞针（在 2K 长文里藏一个事实，看模型找不找得回）。

　　回到小节标题的问题：小模型要不要中间训练？答案是「看需求，但随时能做」。minimind 这类几十 M 的玩具模型，预训练一共就跑几个小时，「主训省钱、中期补强」的分阶段收益本来就不大；但真遇到长文本需求，它的中期训练也简单——不用分六轮、不用算 YaRN 参数，换一份长数据、低学习率续训几百步就完事。

中间训练的本质是资源约束下的分阶段策略：主训承担最贵的通用能力养成，中期用小钱补长上下文、领域配比与数据质量收尾。规模越小，要补的课越少、流程越可以简化——minimind 扩 2K 连 RoPE 都不用碰。这正是 6.2 节「模型越小、配方越可以粗放」在中期训练上的翻版。

8.5.3 风险与监控清单

　　中期训练改了数据、改了长度、动了收尾配比，任何一刀都可能切伤已有能力。工程上盯三类风险：

灾难性遗忘

长文或领域数据占比一升高，通用能力可能回退。对策：中期前后各跑一次通用基准，并保留主训 checkpoint 做对照组。

长短能力跷跷板

加长上下文后短任务变差是常见病——Llama 3 才把「短上下文评测完全恢复」列为每轮验收的第一条。对策：长短混喂（Qwen2.5 Turbo 的 40% ＋ 60% 配方），两侧同时监控。

退火数据失控

退火段 token 量小，单条数据影响被放大；混入低质内容或评测集内容，都会直接刻进终模。对策：退火数据单独设质量门槛，并与评测集严格去重。

　　风险要靠评测组合来抓，单跑一个基准等于蒙眼开车。推荐三线并行的监控组合：

监控线代表基准防什么
通用能力线MMLU、BBH、GSM8K 等通用知识与推理基准遗忘：中期训练后通用能力回退
长文能力线大海捞针（NIAH）、RULER、∞Bench、ZeroSCROLLS标称长度注水：RULER 的实测显示，多家模型捞针满分、真实长文任务却明显掉分——只过捞针不代表长文能用
领域能力线目标领域专属集（代码 HumanEval、数学 MATH，或行业自建集）适配跑偏：领域提升是否兑现、代价是多大
别拿训练 loss 当验收标准。中期训练换了数据分布，新 loss 和主训 loss 没有可比性——长文数据上 loss 低，可能只是数据好猜。唯一可信的验收是上面这套评测组合。
去污染是红线，退火段尤其要命：好数据常和评测题同源。Qwen2.5 的做法可作参考——训练序列与任一评测序列的最长公共子序列达到 13 token 且占较短一侧的 60% 以上，整条剔除。退火数据里混进评测集，分数再高也是自欺欺人。

8.5.4 全章收束与下一站

　　回看第 8 章走过的路：8.1 节给中间训练定位——它是预训练与后训练之间的一条补强带；8.2 节解决「位置装不下」的问题，ABF、NTK、YaRN 三种 RoPE 缩放手法各有适用面；8.3 节解决「长数据从哪来」，拼接、收集、合成三条路；8.4 节讲退火，把学习率与数据质量在收尾段一起拧到位；本节则把四条线落到四个真实方案与一份 minimind 实验清单上。

　　走完这一章，手里的模型已经今非昔比：上下文长度达标、领域配比修正、高质量数据收尾，checkpoint 还做了平均。但请冷静——它依然只会「续写」：给它半句话它接下半句，可你对它说「请帮我总结这段话」，它很可能把你的指令也当成待续写的文本，自顾自往下编。会知识与会听话是两回事，中间训练管的是前者。

第 8 章一句话：中间训练是大模型流水线的补强带——花预训练零头的算力，把上下文长度、领域配比、数据质量收尾三件事补齐，为后训练交出一个更值钱的 base model。

　　让模型从「会续写」变成「听指挥」，靠的是下一章的主角：监督微调（SFT）。第 9 章会讲指令数据怎么构造、对话模板怎么套，以及个人玩家的救星 LoRA——只训百分之几的参数就能完成微调，让 minimind 这样的小模型在单张消费级显卡上也能学会听指令。

主训用短上下文省钱，中期靠「改 RoPE ＋ 长数据短训」扩长度，收尾一律高质量数据退火并复用或平均 checkpoint；没有一家为长上下文从头重训，差异只在分几段、混多少长数据、退火多陡。
把 minimind 从 340 扩到 2048 上下文，最不需要动的是哪部分？
位置编码——配置里 RoPE 基频已是 10⁶、频率表预算到 32K，2K 远在覆盖区内，连 YaRN 开关都已内置。真正要动的只有数据侧（换长数据）与训练侧（从 checkpoint 低学习率续训几百步）。
为什么中期训练必须同时监控通用、长文、领域三条评测线？
改数据分布会带来遗忘与长短跷跷板风险，单看一条线必然顾此失彼；且大海捞针单测会被「标称长度注水」骗过（RULER 实测：捞针满分不代表真实长文任务可用），三线合起来才分得清真提升与障眼法。
