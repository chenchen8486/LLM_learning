## 0. 速查：一节页面的标准骨架

```html
<article class="content">
  <h1>2.1 BPE：从字节到词表的合并艺术</h1>
  <p class="subtitle">本页范围：第 2 章第 1 节　|　整理时间：2026-09-22</p>

  <!-- ① 快速浏览卡片 -->
  <div class="doc-meta-card"> … </div>

  <!-- ② 本节导读：1 到 2 个自然段 + 小节路线图列表（见 §2.3） -->
  <p>　　本节要解决的问题、展开主线 ……</p>
  <ol><li><strong>小节名</strong>（2.1.1）：一句话看点</li></ol>

  <!-- ③ 分级讲解：h2 / h3 用阿拉伯数字编号，如 2.1.1 -->
  <h2>2.1.1 …</h2>
  <p>…</p>

  <!-- ④ 公式 / 配图 / 表格 / 重点框 按需穿插 -->

  <!-- ⑤ 末尾要点回顾卡片（附录章免，见 §1.1 附录章约定） -->
  <div class="socratic-card"> … </div>

  <!-- ⑥ 参考来源（附录章免） -->
  <h2>参考来源</h2>
  <ul><li>…</li></ul>
</article>
```

　　页面的导航侧边栏、面包屑、上下节翻页、`<head>`（含 KaTeX/字体/全局 CSS）均由 `build.py` 自动注入，片段中不要手写。

## 1. 文件与命名约定

### 1.1 章节组织原则

- 每章对应若干 HTML 页面，一节一个文件。节的划分按内容逻辑自定，单页篇幅以讲透一个主题为准，过长就拆节。
- 页面 `<h1>` 标题采用“节号 + 主题”形式（如 `2.1 BPE：从字节到词表的合并艺术`），主题名可自拟，要求准确具体。主题必须亮出本页核心技术的类别关键词，同章相邻小节标题要能互相照应（如 `3.3 绝对位置编码：正弦与可学习两种方案` 与 `3.4 相对位置编码：RoPE 与 ALiBi` 的对仗），让读者从导航就能看清各节分工。
- 附录章：放在手册最后，建在 `pages/ch90_{节}_{短名}.html`（章号 90，构建脚本按此识别，导航标题取“附录 数学与深度学习基础速览”）。页面内编号用 `A.1`、`A.1.1`（不带阿拉伯章号），导读路线图的条目与 h2 对照规则不变。附录只讲手册实际用到的基础数学与概念，不写成通用教材。附录页不写“本节要点回顾”卡片，也不写参考来源区块，正文讲完即止，只留干货。正文末尾加一个 `<h3>本书用在哪</h3>` 区块，用表格列出这个基础点出现在哪些章节、各自用它做什么，让读者知道学它是为了哪一节。样板为 `ch90_1_vectors_rotation.html`。

### 1.2 文件名格式

　　文件名统一采用：

```
ch{章号}_{节序号}_{英文短名}.html
```

| 字段 | 说明 | 示例 |
|------|------|------|
| `{章号}` | 对应开发方案第 3 节的章号，0 到 16，附录为 90 | `2`、`4`、`90` |
| `{节序号}` | 章内页面序号，从 1 开始连续编号 | `1`、`2`、`3` |
| `{英文短名}` | 该节内容的英文短标识，小写下划线 | `bpe`、`rope`、`scaling_law` |

　　示例：

- `ch0_1_pipeline.html`：第 0 章第 1 节，LLM 流水线总览
- `ch2_1_bpe.html`：第 2 章第 1 节，BPE 分词
- `ch4_2_multihead_attention.html`：第 4 章第 2 节，多头注意力

### 1.3 其他约定

| 项目 | 约定 |
|------|------|
| 片段存放目录 | `output/html/pages/` |
| 成品输出目录 | `output/html/` 根目录（build.py 生成，非 `dist/`） |
| 文件编码 | UTF-8（有无 BOM 均可，build.py 读取端兼容，成品由模板声明 charset） |
| 唯一 h1 | 每个片段必须且只有一个 `<h1>`，build 据此提取页面标题 |
| 四级格式 | `ch{章}_{节}_{子节}_{短名}.html` 仍被 build.py 解析为分组，除非确有需要否则不用 |

## 2. 顶部固定结构

### 2.1 标题与副标题

```html
<h1>2.1 BPE：从字节到词表的合并艺术</h1>
<p class="subtitle">本页范围：第 2 章第 1 节　|　整理时间：2026-09-22</p>
```

- subtitle 用于溯源，统一格式“本页范围：<章与节> | 整理时间：<日期>”。

### 2.2 快速浏览卡片 `.doc-meta-card`

　　每节开头必备，给出本节的电梯概览。固定用一个 `.doc-meta` 表格，最后一行放关键词标签。

```html
<div class="doc-meta-card">
  <h3 class="doc-meta-title">快速浏览</h3>
  <table class="doc-meta">
    <tbody>
      <tr><td>核心问题</td><td>……</td></tr>
      <tr><td>本节主张</td><td>……</td></tr>
      <tr><td>一句话结论</td><td>……</td></tr>
      <tr><td>关键词</td><td>
        <div class="keywords"><span>标签A</span><span>标签B</span><span>标签C</span></div>
      </td></tr>
    </tbody>
  </table>
</div>
```

- 左列为固定宽度的标签名（如 核心问题/本节主张/关键词），右列为内容。
- 行数不固定，按内容增减。`.keywords` 内每个 `<span>` 渲染为一枚胶囊标签。

### 2.3 本节导读（快速浏览卡之后的开场段）

　　快速浏览卡之后、第一个 `<h2>` 之前，必放一段开场导读，样板参照 `ch3_1_word_embeddings.html`。导读要回答三件事：本节解决什么问题（最好承上启下，接住上一节的话头）、沿什么主线展开、读完能带走什么。结构为：一到两个正文自然段（遵守两个全角空格缩进）+ 一个小节路线图列表（`<ol>`，逐项给出小节编号、名称与一句话看点），结尾可用一句话点明本节落脚点。约束：

- 导读是叙事引导，不是快速浏览卡的复述：meta 卡给结论，导读给路径。
- 路线图的小节编号与名称必须与页面实际的 `<h2>` 逐字一致，写完回头核对。只列正文小节，不含“参考来源”。
- 列表项不缩进。导读段与正文段落同规则。

## 3. 正文排版约定

| 元素 | 用法 |
|------|------|
| `<h2>` | 节内二级标题，用阿拉伯数字编号，如 `2.1.1 BPE 的合并过程` |
| `<h3>` | 三级标题，同样用阿拉伯数字，如 `2.1.2 词表大小的权衡` |
| `<h4>` | 四级描述性小标题（大写灰色小标题，少用），不编号 |
| `<p>` | 普通段落 |
| `<ul>/<ol>` | 列表，关键步骤用有序列表 |
| `<blockquote>` | 引用资料原话 / 举例句子 |
| `<strong>` | 关键术语、结论加粗强调 |
| `<code>` | 行内代码 / 变量名（非数学公式） |
| `<pre><code>` | 代码块 / 数据流示意（深色背景） |

- 编号规则：本手册不再绑定论文编号。`<h1>` 用“章.节”两级（如 2.1），`<h2>` 用三级（如 2.1.1），`<h3>` 用四级（如 2.1.1.1 较少用）。同一章内编号连续，全手册风格一致。描述性小标题用 `<h4>`，不编号。
- 段落缩进：正文每个自然段（`<p>`）开头空两格，写两个全角空格（U+3000），遵循中文书写习惯。卡片内部、表格、列表内的文字不缩进。
- 讲解风格：对标斯坦福等高校公开课水平，再高深的主题也要让非本专业读者听懂并感兴趣。深入浅出，先给直觉或类比，再上公式。恰当的例子贯穿全篇。重要结论用重点框（见 §5）突出。
- 承上启下：适当点出与前后章节的关系，呼应生命周期主线（如分词章末尾指向 Embedding 章）。
- 图文配合：能画出来的结构不要只靠文字堆。范围限定为附录页与之后新写的页面：每页至少配 1 张原创示意图，凡讲流程、结构、数据流、形状变化、曲线趋势的内容必须配对应图，单页正文超过 6000 字时配到 2 张以上。图要与正文对得上，下方 `.diagram-caption` 说清它在讲什么，不与相邻表格重复表达同一组信息。图的位置：先有清晰的文字介绍，图跟在对应文字之后做印证与可视化，不拿图当开场，不让读者先看图再找解释。已完成的主线章节（第 0 至 8 章）一律不改动，不做配图追溯。附录样板为 `ch90_1_vectors_rotation.html`（向量三栏图、矩阵基向量去向图、旋转图、分组图共 4 张）。
- 面向所有读者的口吻：正文写成公开资料，不写成对某位提问者的回应。“现在回答你的疑问”“你可能想问”“顺便说一句”这类对话式措辞一律不用，改成陈述句或设问句（例如直接问“旋转矩阵里的 cos、sin 是哪里来的”）。第二人称“你”尽量少用，能省则省，改成无主语或“读者”。附录页尤其注意，它是资料，不是答疑记录。
- 技术陈述的限定与无歧义：陈述必须带齐关键限定（适用条件、方向、范围、例外），不说过满的话。漏掉限定会让读者推出错误结论，对照病例见 3.4.1：只说“相隔几站”，无法区分“猫追狗”与“狗追猫”，修订版补上“带方向的位移”。举例要真正支撑论点，反例见 2.3：拿高频后缀 `##ing` 佐证“绑定强就容易合并”，而按公式它恰因分母大被拉低。类比不得推出错误直觉。把特定条件下的结论说成普遍成立，属过度概括。写完回头验算：例子能否反推回论点，数字能否被读者按文中公式复现。
- 术语首现：本页第一次出现的核心术语，若前文（前面各章节与本节之前的段落）没有交代过，必须就地给出一句最小可用解释，或明确指向讲解它的章节，不能让读者带着空白往下读。指向后文是允许的，写成“某某（第 X 章细讲）”即可。对照病例：3.4 节用到 query / key 时全书从未介绍过，第 4 章才讲，已在 3.4.2 补前置说明。正例是 KV Cache 首现处即标“第 13 章细讲”。反过来，前文已定义的术语直接使用，不必重复解释。

## 4. 公式（KaTeX）

| 类型 | 定界符 | 示例 |
|------|--------|------|
| 行内公式 | `\( … \)` | 维度 `\(d_k\)`、序列长度 `\(n\)` |
| 行间公式 | `\[ … \]` | 居中独立成行 |

- 引用资料中的 `$…$` / `$$…$$` 必须转换为上述定界符，不要直接用 `$`（KaTeX 未配置美元定界符）。
- 公式卡片 `.formula-card`：行间公式的推荐容器，公式下方用 `.formula-note` 写解读。
- 符号注解（硬性）：凡含新符号的非平凡公式，`.formula-note` 必须先给一句话白话解读，再给“符号说明”，逐个解释符号的含义与来源（如 \(Q\) 是查询矩阵，由输入乘投影矩阵 \(W^Q\) 得来），样板参照 `ch3_1_word_embeddings.html` 的公式 (2)。平凡公式可不注：如 \(V \times d\) 这类尺寸连乘、纯代入数字的算术式。
- 行内公式里的新符号，首次出现处要在紧跟的正文里用一句话说清（如“\(d_k\) 是注意力头的维度”），不必套符号说明格式。

```html
<div class="formula-card">
  \[ \mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V \tag{1} \]
  <div class="formula-note">公式 (1)：Transformer 的心脏——用 Query 与 Key 的匹配度给 Value 加权求和。符号说明：\(Q,K,V\) 分别是查询、键、值矩阵；\(d_k\) 是键向量维度；\(\sqrt{d_k}\) 是缩放因子，防止点积过大把 softmax 推进梯度极小的区域。</div>
</div>
```

- 多行公式可在一个 `.formula-card` 内连写多个 `\[ … \]`。
- 编号用 `\tag{n}`，同一页面内编号连续。
- 公式内的 `<`、`>`、`&` 必须写成 HTML 实体（`&lt;`、`&gt;`、`&amp;`）。浏览器会把 `<t` 这类序列当成标签起点吞掉后续内容，KaTeX 输入被截断，公式必然渲染错乱（真实病例：`x_{<t}` 写成 `x_{&lt;t}` 才对）。

> 注意：KaTeX 定界符在 `template.html` 中写作 `'\\('`（HTML 源码两个反斜杠），不可多写转义。此为模板维护项，编写片段时无需关心。

## 5. 重点框 `.highlight-box`

　　四种语义色，通过附加 class 切换：

```html
<div class="highlight-box">……</div>            <!-- 绿色：核心要点 / 正面结论 -->
<div class="highlight-box info">……</div>        <!-- 橙色：注释类（自动带“注释”标签） -->
<div class="highlight-box warn">……</div>        <!-- 黄色：注意（自动带“警告”标签） -->
<div class="highlight-box danger">……</div>      <!-- 红色：易错（自动带“易错”标签） -->
```

| 变体 | 颜色 | 标签 | 适用 |
|------|------|------|------|
| （默认） | 绿 | 无 | 仅用于本节核心结论、关键要点 |
| `info` | 橙 | 注释 | 注释类内容统一用此色：补充说明、背景、注释性标注 |
| `warn` | 黄 | 警告 | 注意事项、问题所在、矛盾 |
| `danger` | 红 | 易错 | 易错点、强约束（如掩码、维度限制） |

　　颜色纪律：注释类内容（补充说明、背景、名词注释）一律橙色 info，术语详解卡片 `.term-card` 同属注释范畴，也是橙色系。卡片标签（注释/警告/易错）由 CSS 自动渲染，片段中不要手写。同一页面不得用多种颜色表达同一类内容。绿色只留给真正的核心结论，避免满页花花绿绿。

## 6A. 术语详解卡片 `.term-card`（初学者友好）

> 面向初学者，把专业词汇掰开揉碎：中文名 + 英文词源 + 通俗解释 + 生活化类比。每出现一个对初学者陌生的关键术语，优先用此卡片讲透。属注释类组件，橙色系，卡片左上角自动渲染“术语”标签（CSS ::before，片段不用手写）。

```html
<div class="term-card">
  <div class="term-name">
    <span class="term-zh">分词器 Tokenizer</span>
    <span class="term-en">tokenize = 把文本切分成模型能处理的最小单位</span>
  </div>
  <div class="term-body">
    <p>分词器负责把原始文本<strong>切成一串 token</strong>……</p>
    <div class="term-analogy">就像切菜，把一整根黄瓜切成大小均匀的片，每一片就是锅铲（模型）一次能处理的分量。</div>
  </div>
</div>
```

- `.term-zh`：中文术语名（橙色加粗）。`.term-en`：英文原词 / 词源解释（灰斜体）。
- `.term-body`：通俗讲解段落。
- `.term-analogy`：生活化类比，自动加前缀“打个比方”。强烈建议每个术语卡片都配一个类比。

## 6B. 原创示意图 `.diagram`（自制 SVG）

> 当引用原图过于学术、或某流程/结构需要更直观呈现时，用内联 SVG 手绘示意图。必须明确标注“原创示意图 · 非论文原图”以区别于引用配图。

```html
<div class="diagram">
  <span class="diagram-tag">原创示意图 · 非论文原图</span>
  <svg viewBox="0 0 720 300" xmlns="http://www.w3.org/2000/svg" font-family="Noto Sans SC, sans-serif">
    <!-- 用 rect / text / line / path + marker 绘制流程 -->
  </svg>
  <div class="diagram-caption">图示：……一句话说明这张图在讲什么。</div>
</div>
```

- `.diagram-tag`：左上角紫色胶囊标签，固定写“原创示意图 · 非论文原图”。
- SVG 用 `viewBox` 自适应缩放，`font-family` 设为 `Noto Sans SC` 保持中文一致。
- 配色沿用主题：主结构用紫 `#6d28d9`，对比用青 `#0891b2`，强调/警示用红 `#dc2626`，语义数据用琥珀 `#fef3c7`。
- 箭头用 `<defs><marker>` 定义复用。
- `.diagram-caption`：图下说明。

### 6B.1 图编号（全手册统一，2026-10-09 起强制执行）

- 每页的所有图（定位条、局部放大图、正文原创示意图、引用论文原图）按在页面中的出现顺序统一编号：图 1、图 2、图 3……每个 `.diagram-caption` / `.img-caption` 一律以“图 N：”开头。
- 配定位双图的页面：定位条 = 图 1，局部放大图 = 图 2，正文配图从图 3 起。不配定位条的页面（第 12 章及以后，见 §6C 适用范围）：全部图从图 1 起编号。
- 引用论文原图时，本手册编号与论文原编号各自独立：图注开头用手册编号，末尾注明原编号，如“图 4：Transformer 整体架构（来源：Attention Is All You Need 原论文图 1）”。
- 正文提到图必须带编号：同页写“图 N”，跨页写“X.Y 节图 N”。禁止“上图”“下图”“前面那张图”这类无编号指代。新增或删除图后，必须重排本页后续编号并同步改正文引用。

### 6B.2 SVG 内的公式与符号排版（2026-10-13 起）

- 图内公式符号禁用 ASCII 裸写法（`W^DKV`、`c_t^KV`、`h_t` 这类带 `^`、`_` 的写法一律不用），必须用 `<tspan dy>` 排出上下标，观感对齐正文 KaTeX。规则：下标 `dy` 取正、上标 `dy` 取负、后续内容用反向 `dy` 回到基线，上下标字号取所在文本的 0.7 倍左右。
- 写法示例：`<text>c<tspan dy="2.5" font-size="8.5">t</tspan><tspan dy="-9" font-size="8.5">KV</tspan></text>` 渲染为 \(c_t^{KV}\)。上下同标（如 \(W_i^{UK}\)）先下标后上标连续偏移，再有后续文字时第三段回基线。
- 图内符号与正文公式同一写法：正文公式写 \(W_i^{UK}\)，图里就不许写 W^UK 或 WUK，下标上标一个不缺。
- marker id 全页唯一：同页多张 SVG 各自定义专属箭头 id（如 arr5、arrM53、arrS53），不得跨图复用同名 id，否则后画的图会引用到先画图的 marker 定义，属于无效 HTML。
- 样板：`ch5_3_mla.html` 全部三张图。

### 6B.3 矩阵与向量图形约定（2026-10-13 起）

- 身份标注：图中每个矩形必须一眼读出身份，名称之外标注“向量”或“矩阵”加形状。向量写 `[1, N]`，矩阵写 `[行, 列]`。
- 形状与记号一致：`[1, N]` 行向量画横条，内部竖线表示列分隔。`[5120, 512]` 这类行多列少的矩阵画竖高块。图形轮廓必须对得上数字，不许把非方阵画成正方形。
- 连接符算式化：操作数与权重矩阵之间写 ×，矩阵与结果之间写 ＝，整行读下来就是一条算式（如 `[1, 5120] × [5120, 512] = [1, 512]`）。只有函数处理（RoPE、softmax 这类非矩阵运算）与分支走向保留箭头。乘法已由 × 表达，图例不再用文字重复解释。
- 图例色块化：图例压成一行，色块或箭头小样加短语（如 紫框＝权重矩阵（参数）、青块＝进缓存、紫箭头＝内容通道），禁止两行以上的文字叙述版图例。
- 紧凑优先：viewBox 贴合内容边界，不留大片空白区。散落的对比注记合并为居中横排。数量对比按真实比例画（如 32768 对 576 的横条长度比约 624:11）。
- 前导 1 的去留：单向量参与矩阵乘法时写 `[1, N]`，让 `×`、`＝` 两侧对位整齐。代码四维张量（batch, heads, seq, dim）进图一律砍掉 batch 维，写 `[10, 768]` 不写 `[1, 10, 768]`。判断标准只有一条：读者能否顺着形状把算式读出来。
- 样板：`ch5_3_mla.html` 图 3（MLA 矩阵视角）。

### 6B.4 图注唯一与渲染验看（2026-10-13 起）

- 图注唯一：每图有且只有一份 `.diagram-caption`。整块替换 SVG 后必须 grep 本图编号前缀，确认旧图注无残留（真实病例：ch5_3 图 3 图注曾残留两份）。
- 渲染验看手法：抽取 SVG 用 Edge headless 截图验看。宽高比大于 2 的宽扁 SVG 独立文件在 Edge 下渲染异常（内容缩聚一角），需包一层 HTML（`svg{width:100%;height:auto}`）再截，或直接截取构建后的成品页面局部验看。
- 任何图交付前必须渲染自查：框内留白、元素间距、文字是否重叠或越界、形状与数值是否一致、箭头是否指向正确。不合格改了再交付。

## 11. 完整性验证（强制红线）

> 最高质量红线：每编写完一章，必须对照内容来源逐项核对，关键公式、图表、数据不得缺失或失真。LLM 主线章节的核对基准是第 9A 节列出的一手资料；第 4 章（架构精讲）额外对照 `ref_paper` 原文逐项核对。

### 11.1 验证范围

| 核对项 | 标准 |
|--------|------|
| 公式 | 来源资料中的核心公式必须全部转写为 `\[ … \]` 出现在对应小节，编号用 `\tag{n}` |
| 数据表 | 来源资料中的关键数据表（结果表、消融表、复杂度表）不得遗漏 |
| 引用图 | 引用的图片必须实际被 build.py 复制到 `images/ch{章}/` 目录下 |
| 行内变量 | 正文涉及的关键变量/符号（如 \(d_k, n, h\)）应以公式形式呈现，不丢信息 |
| 参考来源 | 每页末尾的参考来源区块不得为空，列出的资料必须是实际查证过的（附录章免） |

### 11.2 第 4 章专项验证（对照 ref_paper）

1. 清点原始引用：
   ```bash
   cd ref_paper/2016_attention_is_all_you_need
   grep -oE '!\[\]\(images/[^)]+\)' *_zh.md     # 列出所有图片
   grep -c '^\$\$' *_zh.md                        # 行间公式块计数
   grep -oE '\\tag\{[0-9]+\}' *_zh.md             # 编号公式
   ```
2. 核对 html 产出：对上一步每个图片名 / 公式，在第 4 章 `ch4_*.html` 中 `grep -l` 确认存在。
3. 核对复制落地：`ls output/html/images/ch4/ | wc -l` 应与引用图片数一致。
4. 发现缺失立即补全，再重新构建。
5. 只有图片数一致、公式逐条命中后，该章才算可交付。

### 11.3 其余章节验证

1. 逐页检查参考来源区块是否存在且非空（附录章免）。
2. 抽查核心公式与数据，对照所列来源原文核实。
3. 检查所有标注（待查证）的位置是否已在参考来源中说明。
4. 附录章按“无要点回顾卡片、无参考来源区块”检查，确认正文以“本书用在哪”收束。
5. 附录页按 §3 图文配合条款清点配图（`grep -c '<svg'`），确认每页至少 1 张示意图、图注齐全、图与正文对得上。已完成的主线章节不做配图清点与追溯。
